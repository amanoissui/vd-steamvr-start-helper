# VD SteamVR Start Helper

Virtual Desktopの「Emulate SteamVR Vive trackers」を使う際のSteamVR起動を補助する、Windows向けの非公式ツールです。日本語の画面で操作します。

**試験版です。** VDアドオンを一時的にブロックしてSteamVRを起動し、準備完了後にブロックを解除して再起動する手順を補助します。VDやSteamVRの内部の不具合を修正するものではなく、すべての環境での改善を保証するものではありません。

トラッカーの位置計算とコントローラー操作には、VDとSteamVRの元の処理を使用します。独自のトラッカードライバーは追加しません。

## できること

- SteamVR停止中に、VirtualDesktopアドオンだけを一時ブロックします。
- VDから起動したSteamVRの準備完了を確認します。
- 「再起動開始」を押すと、VDのブロックを解除し、SteamVRを1回再起動します。
- ボタンを押さない場合、準備完了から90秒後に自動で再起動します。
- 再起動後、VD純正の胸・腕トラッカー5個と通常のコントローラー2個を確認します。

90秒は成功した手順に合わせた余裕であり、必要な最短時間と確認されたものではありません。

## 動作条件

- Windows 64ビット
- Python 3.10以降の64ビット版とTkinter。実際に確認したPythonは3.10です。
- SteamVRとVirtual Desktop Streamerがインストールされ、通常のVD接続ができること
- VDアドオンの設定がSteamVRに作成済みであること
- 現在の判定はQuest 3、通常の左右コントローラー、VDの胸・左右の上腕・左右の前腕の5トラッカーを想定しています。

Python標準ライブラリを使います。pipで追加するパッケージはありません。SteamVRの場所はOpenVRの登録情報から取得します。SteamVRやVDのDLLは同梱していません。

## 使い方

1. このリポジトリをダウンロードして、書き込み可能なフォルダーに展開します。
2. SteamVRを終了します。
3. `start_helper.pyw`を開きます。関連付けで起動できない場合は、このフォルダーで `py -3 start_helper.pyw` を実行します。
4. 補助ツールで「開始」を押します。
5. Quest側のVirtual Desktopで「Launch SteamVR」を押します。
6. ヘッドセットを装着し、左右のコントローラーを使える状態にします。
7. 「準備できました」と表示されたら「再起動開始」を押すか、そのまま90秒待ちます。
8. 「起動完了」の表示後、位置・追従・ボタン操作を確認してからゲームを起動します。

最初の起動では、VDの仮想トラッカーが出ない状態で待ちます。途中で手動のブロック解除を併用せず、補助ツールの処理に任せてください。

確認に使用したQuest側のVD設定は以下のとおりです。このツールはQuest側の設定を変更しません。

| 設定 | 確認時の状態 |
| --- | --- |
| Forward tracking data to PC | ON |
| Emulate SteamVR Vive trackers | ON |
| Emulate Index controllers | OFF |
| Input → Hand tracking | OFF |

## 確認できている範囲

2026年10月5日、以下の1環境で確認しました。

| 項目 | 環境 |
| --- | --- |
| ヘッドセット | Quest 3 |
| PC | Windows 11、RTX 4070 Ti SUPER |
| SteamVR | 2.17.10 |
| Virtual Desktop Streamer | 1.34.22.0 |

手動の「ブロック付き起動 → 解除 → 再起動」は、PC再起動直後に成功しました。

補助ツールv2の90秒待機による自動処理も1回成功し、胸・腕の5トラッカーと通常の2コントローラーが有効であること、位置・追従・ボタン操作が正常であることを確認しました。この自動試験は、同じWindows起動内で別の試験を行った後の結果です。

v2.1は再起動開始ボタンを追加した版です。15件の自動テストに成功しました。次の点は未確認です。

- ボタンで待ち時間を短縮した場合の実機での安定性
- 補助ツールを使用したPC再起動直後の起動
- 複数回のPC再起動、長時間使用、他のPCやヘッドセットでの安定性

## 中断と設定の復元

「中断」を押すと処理を停止します。まだ再起動を要求しておらず、SteamVRも停止していれば、一時設定を開始前の状態へ戻します。

SteamVRが動いている場合は、起動途中のブロック解除を避けるため一時ブロックを残します。SteamVRを終了してから「設定を戻す」を押してください。異常終了後やPC再起動後も、同じ操作で復元できます。

再起動を要求した後はVDを有効のままにし、追加の再起動を繰り返しません。

## ローカルに保存する情報

ツールのフォルダーに、復元用の`pending.json`と、各実行の`runs/`を保存します。`runs/`にはSteamVR設定のバックアップとログが含まれます。ログや設定にはユーザーフォルダー名、端末識別子、インストール先などが含まれることがあります。

このツールにログの外部送信機能はありません。不具合報告には、まず症状・バージョン・画面のメッセージを記載してください。`runs/`や設定ファイルを丸ごと公開することは避けてください。

実行時に生成される情報は`.gitignore`の対象です。Webから手動アップロードする場合も、これらのファイルを含めないでください。

## 開発とテスト

Windows上で実行します。テストはランタイム操作を模擬し、実際のSteamVRを再起動しません。

```text
py -3 -m unittest -v test_helper
```

OpenVR接続には、SteamVRを起動しない`VRApplication_Background`を使います。最初の起動完了まではログとプロセス情報で待機します。設定ファイルへの直接書き込みはSteamVR停止中だけ行い、起動中のブロック解除には公開OpenVR設定APIを使用します。

SteamVRのログ形式とOpenVRのインターフェースバージョンに依存するため、SteamVRの更新により動作しなくなる可能性があります。
